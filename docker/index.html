Laboratorio de Informática Forense

Universidad de Cataluña · Ingeniería Informática · Cohorte 2026-II

Cómo correr el laboratorio en tu computador

Antes de practicar los casos, necesitás tener Docker instalado y saber qué hace cada comando.

¿Qué es Docker y por qué lo usamos aquí?

Docker es un programa que ejecuta "mini-computadoras" virtuales dentro de tu computador real. Cada una de esas mini-computadoras se llama contenedor y arranca en segundos con todo preinstalado: las 56 herramientas forenses (Sleuth Kit, tshark, Volatility, etc.), la evidencia sintética (imágenes FAT32, NTFS, PCAP) y los enunciados.

Sin Docker, tendrías que instalar a mano 30+ herramientas en tu computador, configurar sus dependencias, y descargar las imágenes de evidencia manualmente. Con Docker, son tres comandos y el laboratorio está listo.

El laboratorio corre 100% en tu computador. No toca internet después de descargar la imagen. La evidencia es sintética y todas las acciones quedan en una carpeta local ~/trabajo dentro del contenedor.

Paso 1 · Instala Docker en tu computador

Estos son los enlaces oficiales. Elige el que corresponda a tu sistema operativo.

SistemaInstruccionesTiempo aprox.
Windows 10/11 docs.docker.com/desktop/install/windows-install/
Abre el instalador, sigue los pasos, reinicia si lo pide. Activa WSL 2 cuando lo pregunte.		 10 min
macOS (Intel o Apple Silicon) docs.docker.com/desktop/install/mac-install/
Descarga el .dmg, arrastra Docker a Aplicaciones, ábrelo. Si tienes chip Apple (M1/M2/M3/M4), la imagen corre con emulación (más lento, ~3-5x).		 5 min
Ubuntu / Debian sudo apt-get update && sudo apt-get install docker.io
Agrega tu usuario al grupo docker para no usar sudo en cada comando:		 5 min

Verifica que quedó instalado. Abre una terminal y ejecuta:

docker --version

Debes ver algo como Docker version 24.0.7, build .... Si ves error, revisa la guía de tu sistema operativo.

Paso 2 · Descarga la imagen del laboratorio

Esto baja los 1.2 GB del laboratorio a tu computador. La imagen ya viene con todo: Ubuntu, las 56 herramientas, la evidencia sintética y el portal web interno. Solo lo haces una vez; después queda en caché.

docker pull fabiguaza76/inforense:v1

¿Dónde corre esto? En la misma terminal donde escribiste docker --version. Es decir, en TU computador (no en un servidor). El comando se conecta a Docker Hub (el registro público de Docker) y descarga la imagen al disco duro de tu computador.

Tarda entre 2 y 10 minutos según tu conexión a internet. Verás una barra de progreso con varias capas (cada capa es una parte de la imagen).

Paso 3 · Arranca el contenedor

Este es el comando principal del laboratorio. Crea un contenedor (la mini-computadora) a partir de la imagen, expone el puerto 80 del contenedor como 8080 de tu computador (-p 8080:80), y lo deja corriendo en segundo plano (-d).

docker run -d --name lab-forense \
              -p 8080:80 \
              --memory=2g \
              fabiguaza76/inforense:v1

¿Qué hace cada parte?

  • -d — "Detached". El contenedor corre en segundo plano y tu terminal queda libre para otros comandos.
  • --name lab-forense — le da un nombre para que puedas referirte a él fácilmente (docker stop lab-forense, docker exec ...).
  • -p 8080:80 — mapea el puerto 80 del contenedor al 8080 de tu computador. Cuando abras http://localhost:8080 en tu navegador, hablarás con el servidor web del contenedor.
  • --memory=2g — limita la RAM a 2 GB (suficiente para todas las herramientas).
  • fabiguaza76/inforense:v1 — el nombre exacto de la imagen en Docker Hub, con su etiqueta v1.

Cuando termina, el comando imprime algo como abc123def456...: es el ID del contenedor. Guárdalo por si acaso.

Paso 4 · Abre el laboratorio en tu navegador

Abre tu navegador (Chrome, Firefox, Safari, Edge — cualquiera) y entra a:

http://localhost:8080/

Vas a ver el portal del laboratorio: una página con cinco pestañas (uno por caso), un bloque azul arriba con los comandos que ejecutaste, y al pie, enlaces al sistema de entregas. Esta es tu puerta de entrada a todo lo que vas a hacer.

Si la página no carga, verifica que el contenedor está corriendo:

docker ps

El contenedor lab-forense debe aparecer como Up X minutes. Si no aparece, revisa los logs:

docker logs lab-forense | tail -20

Paso 5 · Accede a la terminal del contenedor (opcional)

Para la mayoría de los casos no necesitás la terminal; el portal muestra cada comando en bloques copiables. Pero en algunas situaciones (incluir archivos, instalar algo extra, ver archivos ocultos), puedes abrir una terminal dentro del contenedor:

docker exec -it lab-forense bash

Apareces como root. Si prefieres el usuario perito (que es el que tiene acceso a ~/trabajo):

docker exec -u perito -it lab-forense bash

Para salir, escribe exit o presiona Ctrl+D.

Paso 6 · Apaga el laboratorio cuando termines

El contenedor consume 2 GB de RAM mientras corre. Cuando termines tu sesión:

docker stop lab-forense

El contenedor queda apagado pero la imagen (1.2 GB) sigue en disco. Para borrar el contenedor y empezar limpio la próxima vez:

docker rm -f lab-forense
docker run -d --name lab-forense -p 8080:80 --memory=2g fabiguaza76/inforense:v1

Lista de comprobación · Antes de empezar los casos

  • docker --version responde con un número de versión.
  • docker pull fabiguaza76/inforense:v1 terminó sin error.
  • docker ps muestra el contenedor lab-forense como Up.
  • http://localhost:8080/ carga el portal del laboratorio.
  • Las cinco pestañas del portal muestran su contenido.
  • Tienes cuenta en GitHub (para hacer las entregas).

Cuando todo esté marcado, empezá con la pestaña Caso 1.

Caso 1 · Fundamentos: hashes e integridad

Lo que enseña un perito cuando apenas empieza: el acta debe ser idéntica bit a bit a la que se firmó en el momento de la cadena de custodia.

Objetivo

Calcular y verificar el hash SHA-256 del acta del caso, demostrar que la copia es idéntica bit a bit al original, y dejar constancia en un mini-informe de lo que encontraste.

Lo que vas a hacer

Tres comandos en cualquier orden, dentro del contenedor (terminal o vía la pestaña de la página).

  1. Calcular el SHA-256 del archivo /evidencia/caso1/acta.txt con sha256sum. Anotás los 64 caracteres hexadecimales.
  2. Verificar con sha256sum -c /evidencia/caso1/acta.sha256. El sistema debe responder acta.txt: OK.
  3. Identificar el archivo con file /evidencia/caso1/acta.txt. Te confirma que es texto plano UTF-8.

Lo que debes lograr

Al terminar estos tres pasos, debes tener en tu cabeza tres valores:

  • El SHA-256 calculado (64 hex caracteres).
  • La respuesta de -c: OK (la huella coincide con la del archivo .sha256) o FAILED.
  • El tipo de archivo según file.

Los tres van al mini-informe.

Después: entrega

Hacé clic en el botón "Entregar Caso 1 →" debajo. Se abre un GitHub Issue con un formulario que te pide tu nombre, correo institucional y los tres valores que acabás de calcular. Pegá también el contenido del mini-informe en ~/trabajo/caso1.txt que tiene cinco líneas. Al enviar, queda Issue público con tu nombre y fecha.

Lo que viene después: Caso 2 (Adquisición), donde el acta es una copia forense de una imagen de disco completa.

Caso 2 · Adquisición y cadena de custodia

Lo que distingue a un perito serio: copiar un disco con verificación de hash durante la copia, no después.

Objetivo

Generar una copia forense verificada con hash de la imagen FAT32 del caso, y verificar la integridad del directorio de archivos de evidencia que el caso trae adjunto.

Lo que vas a hacer

Cinco pasos. La imagen FAT32 está en /evidencia/caso2/caso2-fat32.img y el directorio de archivos sueltos en /evidencia/caso2/evidencia_original/.

  1. Identificar la imagen con file. Debe reportar DOS/MBR boot sector y FAT (32 bit).
  2. Calcular el SHA-256 de la imagen. Este es tu número de referencia para todo el caso.
  3. Hash recursivo del directorio con hashdeep -r. Genera una lista de hashes y luego verifica con hashdeep -r -k. Salida esperada: una línea OK por archivo.
  4. Copia forense con dc3dd, que calcula el hash DURANTE la copia. La copia queda en ~/trabajo/caso2-copia.dd y dos bitácoras (.hashes y .log).
  5. Verificar la copia comparando el hash calculado por dc3dd con el del Paso 2. Si difieren, rehacelo.

Lo que debes lograr

Después de los cinco pasos debes tener:

  • El SHA-256 original de la imagen.
  • Confirmación de que todos los archivos del directorio coincidieron con hashdeep (sin alertas).
  • Una copia local bit-a-bit idéntica a la imagen, con su hash coincidente.
  • El listado de archivos en la imagen FAT32 (mínimo 8 entradas). Aquí descubrirás también el directorio oculto papelera/ con archivos "borrados".

Después: entrega

En "Entregar Caso 2 →" en esta página, enviá tu mini-informe (~/trabajo/caso2.txt) con los resultados de los cinco pasos. Adjuntá también caso2-papelera.md con la lista de los 3 archivos encontrados dentro de la papelera simulada.

Lo que viene después: Caso 3 (Análisis de NTFS), donde el archivo es una imagen NTFS completa con MFT y flujos alternos.

Caso 3 · Análisis de sistemas de archivos y SO

El pan de cada día del perito de Windows: examinar la MFT, leer metadatos por inodo, descubrir flujos alternos.

Objetivo

Examinar un volumen NTFS con Sleuth Kit para listar los archivos del directorio raíz, inspeccionar los metadatos de la MFT y demostrar que se pueden identificar archivos borrados sin montar la imagen.

Lo que vas a hacer

Cuatro pasos. La imagen NTFS está en /evidencia/caso3/caso3-ntfs.img. NO la montes: Sleuth Kit trabaja directamente sobre el archivo.

  1. Identificar el filesystem con file. Debe reportar NTFS.
  2. Listar el directorio raíz con fls /evidencia/caso3/caso3-ntfs.img. Cada entrada tiene un número de inodo (formato r/r 23: archivo.txt).
  3. Inspeccionar metadatos de un inodo con istat <INODO>. Vas a ver tipo, tamaño, permisos, cuatro timestamps (creación, modificación, acceso, modificación de MFT) y, si tiene, flujos alternos (ADS).
  4. Detectar archivos borrados con fls -d. Estos archivos ya no existen físicamente, pero su metadata sigue en la MFT hasta que sea sobrescrita. Con icat podés recuperar el contenido.

Lo que debes lograr

Después de los cuatro pasos debes poder responder:

  • Cuántos archivos vivos hay en el directorio raíz.
  • Para un archivo específico: su tamaño, fecha de creación y si tiene ADS.
  • Cuántos archivos borrados detectaste.
  • Si uno de ellos es recuperable con icat y por qué sí o no.

Después: entrega

En "Entregar Caso 3 →", enviá tu mini-informe (~/trabajo/caso3.txt) con los seis campos que te pide. Si encontraste ADS, adjuntá caso3-flujos.md con el detalle.

Lo que viene después: Caso 4 (Red y memoria), donde el sistema ahora analiza tráfico de red y memoria RAM.

Caso 4 · Forense de redes y memoria

Dos tareas en una: leer un PCAP para encontrar malware, y capturar la memoria de un proceso con la herramienta nativa de Linux.

Objetivo

Detectar patrones de actividad maliciosa en una captura de tráfico de red (dominios DGA-style, canales de mando y control, túneles DNS) y capturar la memoria de un proceso simulado para analizarla con Volatility 3.

Lo que vas a hacer

Parte A · Red (PCAP precargado)

  1. Inspeccionar el PCAP con tshark -r /evidencia/caso4/red_caso4.pcap -c 5.
  2. Contar consultas DNS y respuestas.
  3. Encontrar dominios DGA-style (16+ caracteres hexadecimales + .test) con tshark -Y 'dns.qry.name matches "[0-9a-f]{16,}\\.test"'.
  4. Identificar el canal de C&C: conexiones repetidas a la misma IP en intervalos regulares. Buscá en el puerto 8443.
  5. Encontrar el túnel DNS: subdominios anormalmente largos (40+ caracteres hexadecimales) bajo tunnel.example.test.

Parte B · Memoria del proceso

  1. Abrir dos terminales dentro del contenedor (usá la pestaña de esta página o docker exec).
  2. En la primera, ejecutar incidente. El proceso queda corriendo y genera tráfico simulado. NO es malware real: es un proceso pedagógico.
  3. En la otra, ejecutar capturar-memoria. El script usa gcore para volcar la memoria del proceso y calcula el SHA-256. Al final imprime la ruta del .core.
  4. Analizar el dump con Volatility 3: vol -f ~/trabajo/memoria_incidente_*.core linux.pslist, linux.pstree, linux.netscan.
  5. Buscar cadenas sospechosas con strings: strings ~/trabajo/memoria_incendente_*.core | grep -i "c2.example.test\|tunnel".

Lo que debes lograr

Después de las dos partes debes poder responder:

  • Cuántas consultas DNS totales hay en la captura y cuántas son DGA-style.
  • El intervalo aproximado entre conexiones al C&C (segundos).
  • Si hay túnel DNS, de cuántos paquetes.
  • El nombre del proceso incidente en vol linux.pslist.
  • La conexión activa en el dump (IP y puerto en linux.netscan).
  • Si la cadena c2.example.test aparece en strings.

Después: entrega

En "Entregar Caso 4 →", enviá tu mini-informe (~/trabajo/caso4.txt) con las diez líneas que te pide el formulario. Las dos líneas más importantes son: el hash SHA-256 del dump de memoria y tu conclusión final sobre la evidencia de actividad de mando y control.

Lo que viene después: Caso 5 (Dictamen integrador), que es la redacción del dictamen final del caso. Es el único caso sin evidencia técnica nueva: es escritura.

Caso 5 · Dictamen pericial integrador

Las nueve partes del dictamen pericial + diez declaraciones bajo juramento. Es la mitad de la nota del curso.

Objetivo

Redactar un mini-dictamen pericial formal de 600 a 1200 palabras, con las nueve partes del CGP artículo 226, citando la evidencia recolectada en los casos 1 a 4, y cerrando con las diez declaraciones bajo juramento.

Lo que vas a hacer

No hay práctica técnica. Este caso es escritura. Vas a redactar ~/trabajo/caso5-dictamen.md usando un editor de texto (nano, vim o lo que prefieras) o cualquier editor Markdown. Sigue este orden estricto:

  1. Encabezado e identificación del perito: tu nombre, matrícula, fecha, lugar.
  2. Solicitud: una frase describiendo lo que se pide.
  3. Objeto del dictamen: tres preguntas concretas que el dictamen debe responder (no más de tres).
  4. Marco normativo: citas literales de Ley 906 arts. 415/417/420, CGP art. 226, Ley 1273 art. 269A, ISO/IEC 27037, ACPO, RFC 3227.
  5. Metodología y verificación de integridad: herramientas usadas, procedimiento del hash, bitácora resumida.
  6. Hallazgos: cuatro o cinco con evidencia citada, procedimiento, resultado numérico.
  7. Interpretación: une cada hallazgo con su importancia. Sin adjetivos como "obviamente", "sospechoso", "malicioso".
  8. Conclusiones: lista de tres a seis puntos que responden directamente al Objeto (Punto 3).
  9. Firma y cierre: tu firma, matrícula, lugar, y las diez declaraciones bajo juramento.

Lo que debes lograr

Un mini-dictamen de 600 a 1200 palabras que:

  • Incluye hashes específicos (no "varios" ni "muchos") en al menos tres hallazgos.
  • Menciona evidencia al menos del caso 1 (acta) y del caso 2 (imagen FAT32 + dc3dd).
  • Cita marco legal concreto (Ley 906 art. 415/417/420, CGP art. 226, Ley 1273 art. 269A).
  • Incluye las nueve partes y las diez declaraciones.
  • No contiene ninguna de las palabras prohibidas: obviamente, claramente, evidentemente, sin duda, malicioso, sospechoso, "con la intención de", hacker.

Después: entrega

En "Entregar Caso 5 →", pegá el contenido completo de tu caso5-dictamen.md (las nueve partes + diez declaraciones). El docente revisa la redacción, la presencia de hashes concretos, y el cumplimiento del lenguaje sobrio. Este caso es la base para la sustentación oral (Actividad 3), que vale el 25 % de la nota del curso.

Lo que viene después: con la entrega del Caso 5 cerrás el laboratorio forense. La sustentación oral es el siguiente hito, no es parte del laboratorio Docker.
